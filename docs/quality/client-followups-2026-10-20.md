# Client follow-ups — 20 October 2026

Implemented and verified against the client's links/screenshots:

- Possible duplicates: the entry page explicitly explains that the initial list is for selecting a property to compare, not a declaration that every row is duplicated. Candidate signals remain advisory; nothing is removed automatically.
- Request banners: a destination picker loads the request owner's eligible public pages. A sole destination is selected automatically; several destinations require an explicit choice. The request purpose supplies an initial title. Linked dates are readable and their campaign ownership is explained, with a link to change/schedule the customer request. Publishing/payment checks stay authoritative.
- Featured advertising: saving a linked campaign retains its original seconds and milliseconds. Previously the minute-only editor changed the timestamps and the server rejected the save as `BANNER_INVALID_STATE`. Single eligible destinations are selected automatically, unavailable prerequisites have explanations, and requested advertisers are retained even when outside the first 100 catalog rows. One-language text inputs use the full editor width. Preview typography and the verification seal are clearer.
- Tips/homepage content: each saved item has a preview and a link to its public location. Homepage editing includes a placement diagram, current heading/description preview and an explanation of what content the section controls. Unmapped legacy records are clearly identified and can be explicitly reassigned to an available supported section. Occupied keys are protected by the existing unique index and optimistic versions.
- Hero copy: the preview explains that a populated active banner controls its own heading/description, and links to banner editing. The section text supplies the existing fallback; it does not silently override a customer's banner.
- Images: Tips and About editors now accept optional image URLs, preview them, persist them and project them publicly. Clearing an existing image removes it. About introduction images control the page cover; other About blocks can display their own image. Homepage About uses its managed content image with the existing default fallback.
- Platform settings: the map field is available alongside the office address/hours. The public footer renders configured working hours and opens the map from the office address. Existing contact settings remain supported; the most recently saved namespace containing a map determines its URL. Address/hours-only configurations are not discarded as unconfigured demo contact data.
- Commission history: rows resolve the associated account's available display name and link to its account. No password, email or credential field is added to this projection. Actions are labeled as creation/update rather than raw action identifiers where applicable.
- Roles: authorized users can delete directly from the role list. Unassigned roles can be removed; assigned roles remain protected until staff are moved, preventing accidental access loss.
- Audit: CMS changes record actual public text/image/layout values before and after, with readable field labels and links to the changed record/editor. Technical IDs/version-only noise is suppressed in the comparison. Older logs cannot reconstruct content that was never recorded, and the UI says so.
- Property category defaults: unset and legacy placeholder images use the site's normal logo. Custom supplied images remain unchanged.
- Public layout: category descriptions have positive separation below their headings. Article author/date/reading metadata has additional spacing and an explicit author prefix. Featured content has larger, readable typography.
- Community categories: administration exposes an Add category form. Authorized moderation staff can add bilingual labels with an audited MongoDB transaction. Existing six categories remain supported. New categories appear in the public composer/filters; registered membership is checked when posting. A new category does not bypass post moderation. Duplicate names, unknown keys and unauthorized writes are rejected.
