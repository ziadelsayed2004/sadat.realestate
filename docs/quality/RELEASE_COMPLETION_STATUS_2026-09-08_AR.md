## دورات الأعمال المكتملة فعليًا

هناك **3 دورات أعمال مكتملة بأدلة Frontend/Backend مباشرة** ويمكن نقلها إلى سجل دليل العميل بعد تحديث مصفوفة الاعتماد:

1. **إشراف منشورات المجتمع**: إنشاء منشور خاص، قرار Admin محمي بصلاحية moderation، سبب إلزامي، سجل تدقيق، `expectedVersion`، رفض القرار القديم بـ`409`، النشر وظهور المنشور للعامة، ثم الإخفاء واختفاؤه من العرض العام.
2. **دورة الإعلان والدفع والجدولة**: Draft، إرسال مقدم الخدمة، مراجعة Admin، إصدار عرض سعر، القبول، رفع إثبات الدفع ومراجعته، ثم الجدولة مع منع الجدولة دون إثبات دفع نظيف ومعتمد.
3. **إعدادات SEO حتى العرض العام**: حفظ إعدادات Admin بعقد محمي ونسخة وسبب وتدقيق، إسقاط عام آمن، استهلاك SSR، canonical/title/meta/Google verification، ثم تطبيق نفس السياسة على `robots.txt` و`sitemap.xml`.

وهناك **4 مسارات إصلاح وتشغيل مكتملة** لكنها ليست دورات أعمال مستقلة من دليل العميل:

- تثبيت السايدبار على القسم الحالي، إبقاء المجموعة المفتوحة، وإظهار الرابط النشط في compact rail.
- استمرار الفلاتر والتبويبات بعد empty results من غير refresh، مع استبدال query القديم عند التطبيق.
- إصلاح مسافات وعرض صفحات Admin والإعدادات والإعلانات والإشعارات وسجل التدقيق على RTL/LTR.
- توافق `paymentPlans`/`installmentAvailable`؛ API العقارات في Production أعاد `200` في الفحص السابق.

## ما لا يجوز اعتباره فلو مكتملًا حتى الآن

مصفوفة دليل العميل الرسمية ما زالت تحمل الحالة `MAPPED_PENDING_BACKEND_CYCLE_REVIEW`: عددها **26 رحلة و131 صفًا**، منها 124 ربطًا صريحًا و7 روابط inferred. لذلك الرقم الرسمي للدورات التي غُيّرت داخل هذه المصفوفة إلى Complete هو **0/26**. هذا نقص في تنفيذ وتوثيق فحص الرحلات كحزمة اعتماد، وليس معناه أن كل وظائفها غائبة.

## النواقص البرمجية

### 1. تطبيق بقية إعدادات Admin في الـruntime

واجهات الحفظ والعقود المحمية موجودة، لكن هذه namespaces ما زال يلزم ربطها بالمستهلك الحقيقي واختبار تأثيرها:

- **Property settings**: حدود الصور والصيغ والحجم، سياسة النشر بعد الاعتماد، انتهاء الصلاحية، ورؤية بيانات مقدم العقار.
- **Advertising settings**: المواضع والأنواع والصيغ والأبعاد، مدة صلاحية عرض السعر، وطرق إثبات الدفع.
- **Privacy/Security settings**: إسقاط بيانات تواصل العميل، الملاحظات الداخلية والمستندات الخاصة حسب الصلاحية، timeout جلسة Admin، وسياسة 2FA إذا كانت ستُعتمد فعليًا.
- **Display/Population settings**: اللغة والاتجاه الافتراضيان، page size، عداد السكان وعنوانه وإظهاره في الصفحة الرئيسية.
- **Community moderation policy**: الكلمات المحظورة، الإجراء الآلي، الحد اليومي، وزمن انتظار المراجعة.

هذه هي أكبر فجوة Backend متبقية داخل إعدادات Admin. واجهة SEO هي الوحيدة من المجموعة الجديدة التي أُغلقت حتى المستهلك العام.

### 2. Baselines الواجهة بعد تعديل 64px — مكتملة محليًا

رُوجعت الفروق المقصودة الناتجة عن هندسة Admin الجديدة، وحُدثت **114 صورة مرجعية** للعربية والإنجليزية. ثُبت تحميل أوزان خط Cairo في اختباري الصفحة الرئيسية والمجتمع لمنع تفاوت الالتقاط. نجحت المجموعة البصرية المستهدفة **64/64**، ثم نجحت مجموعة Admin الكاملة **338/338**: 169 اختبارًا بالعربية و169 بالإنجليزية، من دون `--update-snapshots`.

### 3. تغطية API

كل 557 اختبار سلوكي ناجح، لكن بوابة coverage السابقة كانت **78.23% lines** و**79.88% functions** مقابل حد 80%. يلزم إضافة اختبارات ذات معنى للفروع غير المغطاة حتى تصبح بوابة `quality` خضراء بالكامل.

### 4. مصفوفة رحلات دليل العميل

يجب تحويل الرحلات الـ26 من مجرد mapping إلى سجل تنفيذي: preconditions، actor، API mutations، state transitions، projection العامة، negative authorization، conflict، ونتيجة Production بعد النشر. بعدها فقط يمكن إعلان عدد صادق من `26/26`.

## حالة Production والنشر

- الحساب الذي قدمه المالك تم التحقق منه عبر API كدور `admin` صريح، وليس باستنتاج من نجاح تسجيل الدخول.
- Production ما زال يقدم asset hashes قديمة، و`GET /api/v1/public/settings/seo` يعيد 404؛ إذن آخر إصلاحات `main` لم تُنشر.
- API العقارات كان `200` بعد توافق `paymentPlans` في الفحص المباشر السابق.
- GitHub Actions لا يبدأ job بسبب قفل billing على الحساب، وليس بسبب فشل الكود.
- لا توجد deploy workflow في المستودع، ولا SSH key متاح على الجهاز. محاولة استخدام جلسة Hostinger المفتوحة تعطلت لأن native Computer Use pipe غير متاح في الجلسة الحالية.
- بعد توفير قناة النشر يجب إعادة: 102 Admin routes، Pixel 5 width، property APIs، article query، public SEO endpoint، refresh-session behavior، ثم community/ads cycles على Production ببيانات اختبار معزولة.
