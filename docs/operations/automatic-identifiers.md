# Automatic identifiers

New articles, article categories, locations, property types/categories, amenities,
properties, projects, commission policies, About blocks, team members and tips no longer require a
manually typed slug/key. Generation happens in the API. English names provide a
readable base; Arabic-only names use an entity prefix. A UUID suffix keeps equal
names distinct. Name/title edits retain the identifier and its public URL.
Existing API integrations may still supply a valid explicit slug/key.

ObjectIds are already generated by MongoDB. Foreign keys, legal registration
numbers and semantic configuration keys (for example `homepage.hero`) identify
specific records or functions and are not replaced with random values.

After the normal deployment/build, inspect older records with missing identifiers:

```bash
cd /opt/elsadatrealestate/current
node scripts/backfill-identifiers.mjs --env-file /etc/elsadatrealestate/production.env
```

Apply the reviewed plan:

```bash
cd /opt/elsadatrealestate/current
node scripts/backfill-identifiers.mjs --env-file /etc/elsadatrealestate/production.env --apply
```

The script fills only missing/null/blank identifiers in twelve collections,
preserves existing identifiers and ObjectIds, increments existing document
versions, and records each change in `identifier_backfill_history` within the
same transaction. Re-running it is safe. It requires a MongoDB replica set.
Concurrent edits are skipped rather than overwritten; a later run can fill the
remaining records. It never deletes records or sends emails. Output includes
counts, without connection strings or customer data.

Local verification: `node scripts/verify-automatic-identifiers-local.mjs` after
building the API, with an isolated MongoDB replica set on port 27018.
