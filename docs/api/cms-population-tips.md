# Population counter and real-estate tips

The population administration page also includes a manual city-statistics editor for buildings, residential districts, housing units and annual growth. It uses the existing audited, versioned `GET`/`PUT /api/v1/admin/content/display` permissions and publishes bounded integer settings named `city_metric_<metric>`. Public homepage reads use these published settings over matching legacy metrics, including explicit zero; invalid or draft values never replace public counts. Manual inputs are preserved on failed saves. No population key is offered by this editor or accepted by the public manual-statistics projection.

Production population is read automatically from https://worldpopulationreview.com/cities/egypt/sadat-city. The server extracts the exact Sadat City annual estimate (not the rounded summary), records the estimate year and last successful check, and stores it in `cms_population_source_cache`. No historical population value is hard-coded or extrapolated between source updates.

The first public homepage or admin population read retrieves the source with a five-second timeout and a 2 MB response limit. Subsequent reads use the persistent cache. After 24 hours, the next read returns the last verified estimate immediately and refreshes it in the background; a failed check retries after an hour. Concurrent reads in a process share a request. Redirects, invalid numbers, outdated or regressing years and ambiguous city readings are rejected. A failure before any successful retrieval hides the population number; a failure later retains the last verified estimate across server restarts.

`GET /api/v1/admin/content/population` returns `automatic: true`, optional `sourceYear`/`checkedAt`, and no available mutation actions or fictitious administrator attribution. Manual population PUTs are forbidden in production. Legacy manual population records and `population_count` settings do not override the automatic count. `show_population_counter` still controls visibility and `population_label` still controls the heading. Buildings and all other CMS statistics remain manually managed; the source refresh does not write them.

Real-estate tips are localized, ordered, versioned CMS records. Administrators with the existing CMS content permissions manage them through `GET`/`PUT /api/v1/admin/content/tips`; published writes require publish permission, every mutation carries a reason, and updates use the returned version. Public projections include only published and active tips; empty content is a valid safe state.
