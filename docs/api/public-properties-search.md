# Public property listing and search

`GET /api/v1/public/properties` is unauthenticated. It always starts from `status=published` and `active=true`, then applies the allowlisted `kind`, `transactionType`, `projectId`, `propertyCategoryId`, `propertyTypeId`, `deliveryStatus`, `locationId`, `search`, `minPrice`, `maxPrice`, and `bedrooms` filters. `propertyCategoryId` resolves only active child property types. `deliveryStatus` accepts only `ready_to_move`, `under_construction`, or `future_delivery`.

`sort` accepts only `publishedAt`, `price`, `name`, or `slug`; `direction`, `page`, and `limit` are bounded and default deterministically. Unknown keys, Mongo operator-shaped keys, invalid ranges, and unbounded limits are rejected before a query is built. The response contains pagination metadata, separate bounded `categories` discovery-rail facets and `propertyTypes` filter facets, and a safe public property projection. Both facet arrays contain only active taxonomy values with published-property counts. Public cards may project approved source image/type, persisted installment availability, active featured promotion, delivery status, and views. Workflow state, active flags, contacts, provider identifiers, and review fields remain private.

Provider property forms can request `includeAmenities=true` on the same public catalog route. The optional `amenities` response contains active features and nearby services, sorted by order/slug/id, with only public names, descriptions, and IDs. No administrator permissions or private notes are exposed. Ordinary searches omit this field and do not query the amenities collection. Feature/service selections remain optional and save through the existing provider features-services step.
