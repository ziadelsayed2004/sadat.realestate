# التحديث المعتاد للموقع

نفّذ هذه الأوامر من اتصال SSH بالسيرفر:

```bash
cd /root/sadat-release &&
git pull --ff-only origin main &&
sudo bash deploy/native/manage-production.sh update
```

وضع `update` يجهز إصدارًا جديدًا ويفحصه بينما الإصدار الحالي يعمل. بعد نجاح البناء والاختبارات يفعّل الإصدار الجديد، ويعيد تشغيل خدمتي التطبيق مرة واحدة، ثم يفحص جاهزيتهما. توجد إعادة تشغيل قصيرة عند التفعيل؛ هذا الأسلوب لا يضمن نشرًا بلا توقف تمامًا. إذا فشل فحص جاهزية الإصدار الجديد يرجع سكربت النشر للإصدار السابق.

هذا الوضع لا يشغّل إضافة بيانات الديمو أو تنظيفها، ولا يمسح العقارات أو المستخدمين أو الصور المرفوعة. وضعا `empty` و`launch` يخصان عمليات تنظيف منفصلة، فلا تستخدمهما للتحديث العادي.

لا تحتاج أمر تنظيف قاعدة البيانات مع كل تحديث. إذا أبلغ فحص النشر عن نقص مساحة القرص، شغّل أمر تنظيف ملفات الإصدارات القديمة ثم أعد التحديث:

```bash
cd /root/sadat-release &&
sudo bash deploy/native/recover-disk-space.sh &&
sudo bash deploy/native/manage-production.sh update
```

تنظيف مساحة الإصدارات يحافظ على الإصدار الحالي وإصدار الرجوع وملفات MongoDB والملفات الخاصة والنسخ الاحتياطية. لا يحل محل النسخ الاحتياطي المعتاد.
