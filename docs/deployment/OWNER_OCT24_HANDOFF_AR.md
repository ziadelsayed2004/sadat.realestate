# تسليم تعديلات 24 أكتوبر 2026

## التشغيل والإدارة

- العقار المختار يظهر أولًا في قسم العقارات بالرئيسية. إلغاء الاختيار ثم «حفظ التمييز» يستبعده من الرئيسية حتى لو كان أحدث عقار؛ يظل في دليل العقارات إذا كان منشورًا ومفعّلًا وساريًا. إعادة الاختيار تعيده.
- روابط «عرض الكل» في عناوين أقسام الرئيسية تظهر كأزرار ذهبية.
- المقالات: من **الإدارة ← المحتوى ← المقالات** أنشئ المقال، اختر تصنيفًا مفعّلًا، أضف العنوان والمحتوى والصورة ثم انشره. أحدث ثلاثة مقالات منشورة بتصنيفات مفعّلة تظهر تلقائيًا في الرئيسية. الأرشفة أو تعطيل التصنيف يزيلان المقال منها. إعداد عنوان قسم المقالات في «نصوص الرئيسية» يغيّر عنوان القسم فقط.
- البانر: من **الإدارة ← البانرات ← إضافة بانر** جهّز مكان العرض إن ظهر زر التجهيز، ثم اختر الفترة بتوقيت مصر والصور والنصوص. المعاينة المباشرة تعمل قبل الحفظ، ولها عرض هاتف ولابتوب. الحفظ ينشئ مسودة؛ اضغط بعدها «نشر / جدولة».
- **الإبقاء على مقدمة الرئيسية الأصلية** خيار لكل بانر علوي: إذا كان مفعّلًا في إعلان معروض، تظل المقدمة الأصلية أول شريحة ثم تدور صور الإعلانات معها. إيقافه في جميع الإعلانات المعروضة يجعل الشرائح للإعلانات فقط. البحث وهيدر الموقع يظلان متاحين في الحالتين. تفعيل هذا الخيار لا ينشر المسودة.
- يسمح موضع الرئيسية بأكثر من إعلان في نفس الفترة؛ تظل حدود عدد الإعلانات ومواعيد النشر وشروط اعتماد السداد مطبقة. رسائل النسخة القديمة والحد الأقصى أصبحت محددة.
- بطاقة نجاح طلب الحساب وطلب الإعلان تغلق بعد عشر ثوانٍ، ويمكن إغلاقها يدويًا.
- **حساب العارض ← الإعدادات ← الحساب** يعرض الاشتراك ومدته بتوقيت مصر وزر واتساب الإدارة من إعدادات التواصل. بعد تفعيل الاشتراك للمكتب أو الوسيط يظهر محرر الاسم والصورة. ملف الشركة المعتمدة يظل قابلًا للإدارة وفق قواعد الشركات.
- إشعارات الاشتراك داخل حساب العارض: تفعيل، تجديد، تأكيد اشتراك مجدول، بدء المدة المجدولة، انتهاء، وإيقاف. الانتهاء يخفي الهوية المعتمدة على الاشتراك فورًا حسب الوقت، ويصل إشعاره خلال دورة المتابعة التالية، عادة خلال دقيقة. لا تُرسل رسائل واتساب أو SMS تلقائية.
- اشتراك الاسم والصورة لا يمنح بيانات العملاء. الشركات لها أيضًا قواعد مستقلة لاعتماد الملف واتفاق العمولة؛ انتهاء الاشتراك لا يلغي اتفاقًا قائمًا.

## إعدادات العقارات: معنى القيم الفعلية

| الإعداد | معناه والقيمة الافتراضية عند غياب إعداد محفوظ |
| --- | --- |
| المراجعة الإدارية | مفعّلة: يلزم اعتماد الإدارة قبل نشر العقار. |
| النشر بعد الاعتماد | يدوي: الاعتماد وحده لا ينشر العقار؛ استخدم إجراء النشر. التلقائي ينشر بعد الاعتماد. |
| انتهاء الصلاحية | بلا انتهاء افتراضيًا، أو 30/60/90 يومًا. يختفي المنتهي من العرض العام دون حذف سجله. |
| عدد الصور | من 1 إلى 50، الافتراضي 50. تقليل الحد لا يحذف صورًا قديمة. |
| الصيغ | صور العقارات تدعم JPG وPNG: `image/jpeg` و`image/png`، كل صيغة في سطر. |
| حجم الصورة | لكل صورة من 1 إلى 10 ميجابايت؛ الافتراضي 10. |
| التواصل والخصوصية | القوائم لا تعرض وسائل التواصل؛ الهوية تتبع اعتماد العارض واشتراكه، وبيانات العملاء تتبع صلاحيات الطلبات والعمولة. حقول التواصل القديمة محفوظة، لكنها ليست مفاتيح لتغيير هذه القواعد ولذلك لا تظهر كخيارات تعديل فعّالة. |

عرض القيم الافتراضية لا يحفظها تلقائيًا؛ التعديل الفعلي يحتاج سببًا ثم حفظًا. تخفيض حد الصور أو مدة الصلاحية ليس أمر حذف للمحتوى القديم.

## إعدادات العرض

- إحصاءات المدينة: رابط واضح لإدارة الأرقام من صفحة إحصاءات المدينة. عدد السكان يأتي من مصدر السكان المنشور؛ أما الوحدات والمناطق والمباني والنمو فهي أرقام يراجعها المدير.
- إظهار عداد السكان يتحكم في ظهوره عند توفر قيمة منشورة. عنوانه بالعربية والإنجليزية قابل للتعديل.
- كلمات المجتمع: فعّل الفحص، واكتب كلمة أو عبارة في كل سطر، واختر مراجعة المنشور أو رفضه عند المطابقة.
- الحد اليومي: من 1 إلى 100 منشور لكل حساب؛ فارغ يعني بلا حد يومي إضافي.
- مهلة المراجعة: من 1 إلى 168 ساعة للمتابعة، ولا تعني موافقة تلقائية؛ فارغ يعني لا توجد مهلة محددة.
- الزائر يختار اللغة، والاتجاه يتبع اللغة تلقائيًا، ولكل قائمة حجم صفحاتها. القيم القديمة للغة والاتجاه وحجم الصفحة محفوظة ولا تُعرض كمفاتيح عامة غير مطبقة.

## تحديث السيرفر

بعد تأكيد رفع التعديل إلى GitHub:

```bash
cd /root/sadat-release &&
git pull --ff-only origin main &&
sudo bash deploy/native/recover-disk-space.sh &&
sudo bash deploy/native/manage-production.sh update
```

لا يحتاج الأمر إلى `/` في نهايته. النشر عبر GitHub لا ينفذ تحديث السيرفر بنفسه.

## معاينة وتنظيف محتوى التجارب اليدوي والديمو

الأداة الجديدة مختلفة عن `production:launch:purge` القديم الذي كان مخصصًا لإعادة ضبط أوسع. استخدم الأوامر التالية لهذا الطلب؛ لا تستخدم أمر إسقاط قاعدة البيانات أو مسح مجلد الملفات.

الخطة تشمل محتوى الأعمال والحسابات غير الإدارية المرشحة للمراجعة؛ لا يمكن معرفة أن سجلًا أُدخل يدويًا هو تجربة من اسمه وحده، لذلك لا يُختار أي سجل للحذف تلقائيًا. يحتفظ التنظيف بحسابات الإدارة وكلمات مرورها وجلساتها، والإعدادات والتصنيفات والمواقع وإحصاءات المدينة وسجل التدقيق. يحتفظ بالملفات المرفوعة على القرص، ولا يتيحها للزوار بعد حذف السجلات التي تنشرها.

خذ نسخة الإنتاج الكاملة، ثم أوقف الكتابة مؤقتًا حتى لا تتغير الخطة أثناء مراجعتها:

```bash
cd /root/sadat-release
sudo bash deploy/native/trial-content-cleanup.sh backup
sudo systemctl stop elsadat-api.service elsadat-web.service
sudo bash deploy/native/trial-content-cleanup.sh plan /var/backups/elsadatrealestate/trial-content-plan.json
sudo bash deploy/native/trial-content-cleanup.sh show /var/backups/elsadatrealestate/trial-content-plan.json
```

إذا كانت كل السجلات المعروضة تجارب فعلًا، بما فيها التجارب اليدوية، اختر كل القائمة **بعد مراجعتها**:

```bash
sudo bash deploy/native/trial-content-cleanup.sh select-all /var/backups/elsadatrealestate/trial-content-plan.json SELECT_ALL_LISTED_TRIAL_CONTENT
```

وإذا كان بالقائمة سجل حقيقي، افتح ملف المعاينة بـ`sudo nano /var/backups/elsadatrealestate/trial-content-plan.json` واجعل `selected` يساوي `true` للسجلات التجريبية فقط. لا تغيّر المعرفات أو بصمات السجلات. ستُرفض الخطة إذا كان حذف سجل مختار سيترك سجلًا غير مختار مرتبطًا به.

التنفيذ بعد المراجعة:

```bash
sudo bash deploy/native/trial-content-cleanup.sh apply /var/backups/elsadatrealestate/trial-content-plan.json DELETE_REVIEWED_TRIAL_CONTENT
```

يحفظ التنفيذ نسخة EJSON للسجلات المختارة في `/var/backups/elsadatrealestate-trial-content` بصلاحيات المدير، ويتحقق منها، ثم يحذف داخل transaction واحدة. المجلد مستقل عن مجلد النسخ الدورية، وأمر النسخة الكاملة يعمل بحساب خدمة `elsadat` للحفاظ على صلاحيات ملفاتها المعتادة. يطبع التنفيذ مسار النسخة وعدد المحذوفات ويعيد تشغيل API وWeb. إذا تغيرت البيانات منذ المعاينة يرفض التنفيذ؛ أنشئ خطة جديدة باسم ملف جديد وراجعها. عند إلغاء التنظيف قبل التنفيذ أعد تشغيل الخدمات:

```bash
sudo systemctl start elsadat-api.service elsadat-web.service
```

لم تُنفّذ أي عملية حذف على بيانات الإنتاج أثناء تطوير هذه التعديلات.
