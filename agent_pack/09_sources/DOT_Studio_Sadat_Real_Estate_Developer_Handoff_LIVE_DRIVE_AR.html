12 — DATA & STATES

نماذج البيانات والحالات

Provider Account

Draft → Pending Review → Needs Information → Verified / Rejected / Suspended.

Property / Project

Draft → Pending Review → Needs Changes → Approved/Published أو Rejected؛ Hidden/Archived عند الحاجة.

Ad Request

Draft → Review → Waiting Pricing → Quote Sent → Waiting Payment → Scheduled → Active → Ended.

Customer Request

New → Contacted → Follow-up → Viewing → Interested/Negotiation → Completed/Closed وفق نوع الطلب.

Commission

Policy + Account Commission + Exceptions + Effective Date + Confirmation State + Change Log.

Payment Proof

Uploaded → Pending Review → Approved/Rejected؛ الرفع لا يعني تحققاً بنكياً آلياً.

استخدم enums/keys ثابتة في الـbackend مع mapping للترجمات. لا تستخدم النص العربي المعروض كقيمة منطقية داخل قاعدة البيانات.
13 — BUSINESS RULES

قواعد أعمال أساسية

Provider Identity

كل عقار/وحدة منشورة لها مصدر واضح: مطور، شركة، مكتب أو سمسار فرد، ويظهر في Cards وDetails وSearch وSaved وCompare.

Comparison

عنصران فقط؛ السعر، السداد، المساحة، التقسيم، الموقع، المميزات، الصور/المخططات، مقدم العقار، المشروع والمطور.

Ads & Payments

لا يوجد سعر إعلان ثابت عام؛ الإدارة تحدد العرض النهائي. إثبات الدفع يراجع يدوياً ما لم يضاف Integration.

Commissions

نسبة أو قيمة ثابتة أو استثناء/إعفاء حسب السياسة. لا توجد Universal Commission hardcoded.

Verification

Verified Badge يظهر فقط لحالة اعتماد حقيقية.

No Fake Automation

لا AI Matching أو تحقق حكومي/بنكي/ملكية آلي أو Analytics وهمية بدون مصدر بيانات فعلي.

Responsive Completed

لوحة الباحث مخصصة للاستخدام من Desktop فقط في نطاق التصميم الحالي.

Desktop Only
Property Provider & Admin / مقدم العقار والإدارة

لوحات مقدم العقار ولوحة الإدارة مخصصة للاستخدام من Desktop فقط في نطاق التصميم الحالي.

Desktop Only
مهم: عدم وجود روابط مستقلة لنسخ الـTablet والـMobile داخل Drive الحالي لا يعني أنها غير مصممة. النسخ المتجاوبة موجودة ضمن تصميمات Public Website وAuthentication & Onboarding، بينما لوحات Seeker / Provider / Admin تعتمد Desktop فقط.

تعليمات التنفيذ

  • Public Website وAuthentication يتم تنفيذهما Responsive طبقاً لنسخ Desktop / Tablet / Mobile المعتمدة في Figma.
  • Property Seeker Dashboard لا يحتاج Tablet أو Mobile layout ضمن النطاق الحالي.
  • Property Provider Dashboard لا يحتاج Tablet أو Mobile layout ضمن النطاق الحالي.
  • Admin Dashboard لا يحتاج Tablet أو Mobile layout ضمن النطاق الحالي.
  • لا يتم اختراع Responsive behavior للوحات الإدارة الثلاث خارج التصميم المعتمد.
  • اتجاه العربية RTL، بينما English وSimplified Chinese LTR.
16 — API CONTRACT

إرشادات Backend/API

Lists

Pagination أو cursor + filters + sort + search + total/meta.

Details

Entity + permissions + available actions عند اعتماد الأفعال على الحالة والدور.

Mutations

ترجع state الجديدة ورسالة وfield validation errors بمفاتيح واضحة.

Uploads

uploading / success / failed / retry؛ المستندات الحساسة لا تعتمد على public permanent URLs.

حد أدنى متوقع: id، status، createdAt، updatedAt، وبيانات audit/permissions حسب الـentity.
